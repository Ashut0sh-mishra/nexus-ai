## 2. Category-by-Category References

### Category 1: Manus-like Autonomous Agent Runtime

#### OpenManus (FoundationAgents/OpenManus)
- **URL:** https://github.com/FoundationAgents/OpenManus
- **License:** MIT | **Stars:** 15k+
- **Key files to inspect:**
  - `app/agent/` — Base agent classes, tool calling agent, planner
  - `app/flow/` — Multi-agent flow orchestration (planner → supervisor → executor)
  - `app/tool/` — Tool registry with strict schemas
  - `config/config.toml` — Agent step limits, provider config
  - `run_flow.py` — Multi-agent planner/worker entry point
- **NEXUS lesson:** Study the Coordinator → Planner → Executor → Monitor agent hierarchy. OpenManus uses a ReAct-style loop with configurable max_steps. The tool registry pattern with schema validation is exactly what NEXUS needs.
- **Why better than current NEXUS:** OpenManus has battle-tested planner/executor separation, MCP tool integration via `run_mcp.py`, and DataAnalysis agent specialization.
- **Risk:** MIT license is permissive. Code is from MetaGPT team, actively maintained.

#### Suna/Kortix (kortix-ai/suna)
- **URL:** https://github.com/kortix-ai/suna
- **License:** Apache 2.0 | **Stars:** 9k+
- **Key files to inspect:**
  - `backend/agent/` — Agent orchestration, tool dispatch, LLM integration via LiteLLM
  - `backend/agent/tools/` — Tool implementations (browser, file, command, data providers)
  - `backend/agent/tools/data_providers/` — External API integrations (LinkedIn, RapidAPI)
  - `frontend/src/` — Next.js chat UI, dashboard, real-time streaming
  - Agent markdown files — Identity, permissions, tools, triggers per agent
  - Skills system — 60+ reusable knowledge packs
- **NEXUS lesson:** Suna's "agent as markdown file" pattern is powerful — each agent has identity, permissions, tools, and activation rules defined in frontmatter. The skills system (reusable knowledge packs) is a pattern NEXUS should adopt for presentation domain expertise. The autowork loop (work until done, self-verify) is the autonomy model NEXUS needs.
- **Why better:** More production-ready than OpenManus. Has persistent memory, 3000+ integrations, cron/webhook triggers, multi-channel access. Full Linux sandbox per agent.
- **Risk:** Apache 2.0 is safe. Heavy Supabase/Daytona dependency — NEXUS should abstract these.

#### AgenticSeek (Fosowl/agenticSeek)
- **URL:** https://github.com/Fosowl/agenticSeek
- **License:** GPL-3.0 | **Stars:** 26k+
- **Key files to inspect:**
  - Agent router — Dual-model voting (BART zero-shot + adaptive LLM router)
  - `sources/agents/` — Casual, Browser, Coder, File, Planner, MCP specialist agents
  - `sources/llm_provider.py` — Provider abstraction (Ollama, LM Studio, llama.cpp, OpenAI, Google)
  - Session recovery system — `recover_last_session` / `save_session` config
  - `sources/interaction.py` — Conversation flow management, TTS/STT coordination
- **NEXUS lesson:** The agent routing system (BART classifier + LLM voting) is brilliant for auto-selecting the right specialist. Study how they estimate task complexity to decide planner vs direct agent. Session recovery pattern is essential for production.
- **Why complementary:** AgenticSeek excels at local-first routing — NEXUS can learn the router pattern without the GPL dependency.
- **Risk:** GPL-3.0 license — DO NOT copy code. Study patterns only. If NEXUS is commercial, GPL is incompatible. Reference only.

### Category 2: Browser Automation and Tool Execution

#### browser-use (browser-use/browser-use)
- **URL:** https://github.com/browser-use/browser-use
- **License:** MIT | **Stars:** 60k+
- **Key files to inspect:**
  - Core agent loop — How it observes page state and decides actions
  - Accessibility tree extraction — How it reads page structure without screenshots
  - Action schema — Structured tool definitions for click, type, navigate
  - `skills/browser-use/SKILL.md` — Claude Code integration pattern
  - Cloud vs local browser management
- **NEXUS lesson:** browser-use solved the "how to give an LLM a browser" problem at scale. Their approach of using accessibility trees rather than screenshots is more token-efficient. The custom `ChatBrowserUse()` model optimized for browser tasks is a pattern NEXUS could replicate for presentation tasks.
- **Risk:** MIT license, safe to study. They now have a commercial cloud product — the open-source core remains usable.

#### Playwright MCP (microsoft/playwright-mcp)
- **URL:** https://github.com/microsoft/playwright-mcp
- **License:** Apache 2.0 | **Stars:** 15k+
- **Key files to inspect:**
  - MCP server implementation — How tools are exposed via MCP protocol
  - Accessibility snapshot format — Structured page representation
  - Tool definitions — click, fill, navigate, screenshot, etc.
  - CLI vs MCP tradeoffs documentation
- **NEXUS lesson:** This is the reference implementation for exposing browser capabilities via MCP. NEXUS should study this pattern to expose its own presentation capabilities as MCP tools. The accessibility snapshot approach (no vision model needed) is key.

#### HyperAgent (hyperbrowserai/HyperAgent)
- **URL:** https://github.com/hyperbrowserai/HyperAgent
- **License:** Open Source
- **Key files to inspect:**
  - Action caching system — Record/replay without LLM calls
  - `actionCache` format — XPaths, frame indices, execution details
  - `runFromActionCache()` — Deterministic replay
  - `createScriptFromActionCache()` — Script generation from recordings
  - CDP-native element lookup, scrolling, typing
- **NEXUS lesson:** The action caching/replay pattern is gold for NEXUS benchmarks. Record a presentation generation workflow once, replay deterministically for regression testing. This directly solves NEXUS's eval reproducibility gap.

### Category 3: Presentation/Deck Generation Engines

#### Presenton (presenton/presenton)
- **URL:** https://github.com/presenton/presenton
- **License:** Apache 2.0 | **Stars:** 4.8k
- **Key files to inspect:**
  - `servers/fastapi/` — Backend presentation generation API
  - `servers/nextjs/` — Frontend UI
  - API endpoint: `/api/v1/ppt/presentation/generate` — Full generation pipeline
  - Template system — Custom templates with HTML + Tailwind CSS
  - Multi-provider LLM config — OpenAI, Anthropic, Google, Ollama, custom endpoints
  - Image generation — DALL-E 3, Gemini Flash, Pexels, Pixabay, ComfyUI
  - Mem0 integration — Presentation memory with local Qdrant + SQLite
  - LiteParse — Document parsing (PDF/DOCX → slide content)
  - MCP server — Built-in MCP for external agent access
- **NEXUS lesson:** Presenton is the most complete open-source presentation product. Study the full pipeline: content → outline → slide generation → template application → PPTX export. The Mem0 integration for per-presentation memory is a pattern NEXUS should adopt. The API design (`/api/v1/ppt/presentation/generate`) is exactly the interface NEXUS needs.
- **Why this is #1:** Covers presentation generation, templates, multi-LLM, API, Docker, desktop app. Most aligned with NEXUS's presentation product goals.

#### PPT Master (hugohe3/ppt-master)
- **URL:** https://github.com/hugohe3/ppt-master
- **License:** Open Source
- **Key files to inspect:**
  - `skills/ppt-master/SKILL.md` — Complete generation workflow spec
  - `skills/ppt-master/scripts/svg_to_pptx.py` — SVG → native PPTX conversion
  - `skills/ppt-master/scripts/finalize_svg.py` — SVG post-processing
  - `skills/ppt-master/scripts/source_to_md/` — PDF/DOCX/URL/Excel → Markdown converters
  - `skills/ppt-master/scripts/pptx_template_import.py` — PPTX template extraction
  - `skills/ppt-master/scripts/image_gen.py` — Multi-backend image generation
  - `skills/ppt-master/scripts/notes_to_audio.py` — TTS narration
  - `references/animations.md` — OOXML animation reference
  - `examples/` — 20+ complete example projects
- **NEXUS lesson:** PPT Master solves the hardest problem — native editable PPTX with real DrawingML shapes, not images. The pipeline is: Source → Markdown → SVG pages → Native PPTX. This SVG→PPTX approach produces PowerPoint files where every element is clickable and editable. NEXUS should study the template replication system that extracts themes, fonts, and layouts from any .pptx.
- **Why complementary to Presenton:** Presenton gives you the product/API architecture. PPT Master gives you the PPTX generation quality. NEXUS needs both.
- **Risk:** Designed as an AI IDE "skill" (Claude Code/Cursor), not a standalone API. NEXUS would need to extract the pipeline logic.

#### SlideDeck AI (barun-saha/slide-deck-ai)
- **URL:** https://github.com/barun-saha/slide-deck-ai
- **License:** Open Source | **Stars:** 665
- **Key files to inspect:**
  - `slidedeckai/core.py` — Simple LLM → JSON → python-pptx pipeline
  - Template system — Pre-defined presentation templates
  - PDF-to-slides conversion
- **NEXUS lesson:** Good reference for the simplest viable pipeline: prompt → structured JSON → python-pptx assembly. Useful as a baseline to compare against Presenton/PPT Master's more sophisticated approaches.

## 4. NEXUS Implementation Lessons

### Lesson 1: Pipeline Architecture
NEXUS should adopt Presenton's pipeline: **Content → Outline → Slide Layout Selection → Content Generation → Template Application → PPTX Export**. Layer PPT Master's SVG→native PPTX approach on top for higher quality output.

### Lesson 2: Agent Loop
Adopt OpenManus's planner/executor separation with Suna's autowork persistence. The agent should: Plan → Execute → Verify → Loop or Complete. Persist every step for replayability.

### Lesson 3: Provider Abstraction
Use LiteLLM (from Suna) as the provider abstraction layer. Support OpenAI, Anthropic, Google, Ollama, and custom OpenAI-compatible endpoints via environment variables (from Presenton's pattern).

### Lesson 4: Tool Registry
Build a strict tool registry (from OpenManus) where every tool has a JSON schema, version, and validation. Register presentation tools (generate_outline, generate_slide, apply_template, export_pptx) alongside browser and file tools.

### Lesson 5: Benchmark Reproducibility
Implement HyperAgent's action caching pattern — record every agent action during a presentation generation run, then replay deterministically for regression testing. Separate offline evals (rubric scoring on saved artifacts) from live evals (end-to-end generation).

### Lesson 6: Template System
Combine Presenton's template-from-PPTX with PPT Master's OOXML extraction. NEXUS should accept any .pptx as a template input and extract theme colors, fonts, layouts, and images.

### Lesson 7: MCP Integration
Expose NEXUS presentation capabilities as an MCP server (from Presenton's pattern) so external agents can generate slides. Also consume external MCP servers (from OpenManus) for research, data, and tools.
